# Release notes for sbmlsim 0.42.0
![sbmlsim](https://github.com/matthiaskoenig/sbmlsim/raw/develop/docs/images/favicon/sbmlsim-100x100-300dpi.png)

Two changes: the interpolation of data and the data-driven inputs of a model moved from sbmlutils into sbmlsim, and every figure is now drawn by the renderer of sbmlsim-core, which removes matplotlib, seaborn and plotly from the dependencies. The second one changes the look of every figure and a number of plotting APIs, read the lists below before you upgrade.

## Interpolation and data-driven model inputs from sbmlutils

`sbmlsim.interpolation` holds what was `sbmlutils.data.interpolation`: `Interpolation`, `Interpolator`, `InterpolationMethod` and the `INTERPOLATION_*` aliases. A table of data points becomes constant, linear or natural cubic spline assignment rules, which write a standalone SBML model, drive an existing document in place (`drive`), drive a model through comp (`drive_comp`) or become factory assignment rules (`assignment_rules`). The targets are validated before a document is modified, and the driven models are simulated with `Simulator` in the tests. The implementation needs no new dependency. `docs/interpolation.md` is the page, `examples/interpolation/` has three examples which run without network access and save their figures. (#662)

**Migrating from sbmlutils.** Replace imports from `sbmlutils.data.interpolation` with `sbmlsim.interpolation`. The classes, the enum, the method constants and their behavior are the same.

## Figures on the renderer of sbmlsim-core

Every figure is drawn by the renderer of sbmlsim-core 0.28 (`sbmlsim.plot.chart`, `plot/resolve.py`), so figures change their look. The package requires `sbmlsim-core>=0.28.0`. Reports show the figures as inline SVG and are interactive (`figures.js`). (#666, closes #661)

### Performance

| | before | after |
|---|---|---|
| HCTZ experiment figures | 1.05-1.21 s | 0.16 s |
| HCTZ fit report | 18.4 s | 1.54 s |
| Sensitivity figures | 1.73 s | 0.29 s |

### Added

* `Chart`, `ChartPlot`, `ChartAxis` and colour names in `sbmlsim.plot`.

### Changed

* Unknown colour-map names raise.
* Asymmetric `vmin` and `vmax` around a centre are supported.
* `FigureSettings` fields which the contract figure/1 cannot carry are not supported: `fig_facecolor` and `legend_loc` log one warning per figure (the renderer has no background colour, themes come from CSS, and it places the legend itself). The renderer has one title size: `axes_titlesize` for a figure with plot titles and no figure title, `fig_titlesize` otherwise, and a figure with both uses `fig_titlesize` and logs it.
* Numeric font weights of 600 or more (and `"700"`, `bold`, `semibold`, ...) are bold, the only other weight is normal.
* Figure formats are `svg`, `png` and `json`. The `json` spec is always written, the format `html` raises.
* `figures_mpl()` is a warned hook: its figures are saved with `savefig(bbox_inches="tight")`.
* Plot functions return a `Chart` and no longer take `ax=`, `path=` or `dpi=`: `plot_bands`, `plot_distribution`, `plot_heatmap`, `plot_indices`, `plot_morris`, `plot_profile`, `plot_profiles`, `plot_diff` and the `FitReport.plot_*` methods. `draw_boxes` takes a `ChartPlot`.
* `identifiability.plot_all(png_dpi="figure")` writes the PNG at the resolution of the figure itself.
* The section of the console leaves its icon out when the stream is not UTF-8, so a Windows console no longer fails on it.

### Removed

* The dependencies matplotlib, seaborn and plotly. Pillow stays for `verify png`. Both may still be installed transitively.
* `sbmlsim.plot.serialization_matplotlib` (`FigureMPL`, `MatplotlibFigureSerializer`; annotate with `from matplotlib.figure import Figure`) and `sbmlsim.plot.serialization_plotly`.
* `label_axes`, `units.setup_matplotlib` (call `ureg.setup_matplotlib(True)` yourself), `create_mpl_figures`, `save_mpl_figures`, `show_mpl_figures`, `close_mpl_figures`, `save_interactive_figures`, `FigureOutputs.rc` and `rc_params`.
