# Release notes for sbmlsim 0.9.8
![sbmlsim](https://github.com/matthiaskoenig/sbmlsim/raw/develop/docs/images/favicon/sbmlsim-100x100-300dpi.png)

A release of the fits: a fit records what it ran with, and the Fisher information reports the relative error of a parameter. The simulations are unchanged.

## Features

- **Fit results carry their provenance** ([#334](https://github.com/matthiaskoenig/sbmlsim/issues/334), [#337](https://github.com/matthiaskoenig/sbmlsim/pull/337)). Every fit records what it ran with, so that it can be reproduced and reported (`sbmlsim.fit.provenance`, `FitProvenance`): the arguments of the fit (size, algorithm, strategy, seed, study ids, timeout, the optimizer options and the arguments of the caller), the base seed and the seed of every run (`None` for the runs of least squares, which are deterministic and differ in their start values), the versions of python, sbmlsim, libroadrunner, scipy and numpy, the git revision of the repository which contains `base_path` with a dirty flag, the SHA-256 of the SBML models and the data files of the problem (`OptimizationProblem.files()`), the start values of the fit parameters, the values the caller keeps fixed (`run_fit(..., fixed_values=...)`) and the date and time. `run_fit` creates it before the first run; it is in every run JSON and in the result (`OptimizationResult.provenance`, `"provenance"` of `to_dict`, a lossless round trip). A result of a fit before this release reads with `provenance = None`. `docs/fitting.md` has a section "Provenance".

## Fixes

- **The cv of the Fisher information is the relative error of the parameter** ([#338](https://github.com/matthiaskoenig/sbmlsim/issues/338), [#339](https://github.com/matthiaskoenig/sbmlsim/pull/339)). The column `cv` of `FisherInformation.summary_df` (`fisher.tsv` of a fit and its report) divided the standard error in the space of the optimizer by the value in that space, for a parameter searched as log10 `se(log10 p)/|log10 p|`, which depends on the unit of the parameter and is near infinite for a value near 1 (in the HCTZ model of pkdb_models `Emax_hctz_cl` 1.15 had 134 % where its relative error is about 19 %). It is now the relative error of the parameter in the units of the model, to first order (`FisherInformation.relative_errors`): `se/|p|` on the linear scale, `se(ln p)` for ln and `ln(10) se(log10 p)` for log10.
