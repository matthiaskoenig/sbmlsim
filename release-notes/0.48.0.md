# Release notes for sbmlsim 0.48.0
![sbmlsim](https://github.com/matthiaskoenig/sbmlsim/raw/develop/docs/images/favicon/sbmlsim-100x100-300dpi.png)

A fit whose simulation group is a scan is a fit of the engine, and a run starts working sooner: the pool of the experiments starts before the experiments are initialized, a model reads its SBML once, and the engine core simulates a small scan on every CPU.

## Features

- **Scans in the engine** (#691, fixes #624). A simulation group whose simulation is a `Scan` is one condition of the request of the engine per point a curve reads: the plan of a point applies the fitted values first and the values of the point after them, so a dimension still wins over a fitted parameter of its target. A mapping over a dimension is a curve per point, and the reductions and the `PK` parameters of #685 are curves of the point they read. The residuals equal the ones of python; a request grows by about 6 kB per condition, a scan of 1000 points is 6 to 10 MB. Data between two points of a scan and a dimension without `at` which sets the target of a fitted parameter stay the gap `scan`.

## Changes

- **The pool of a run of experiments starts first** (#693). `run_experiments` starts the pool in the background before the runner initializes the experiments (`parallel.start_pool_soon`, `PendingPool`), and every worker initializes an experiment of the run while the parent initializes its own, so the first worker simulates after 5 to 7 s instead of 12 s on the 28 experiments of HCTZ over their draws. Not for a serial run, AMICI, the scan pools of roadrunner and the start method `fork`.
- **A model reads its SBML once** (#692). `symbols.read_document` keeps the document of the text read last per process, shared by the reads of the level, `comp`, the symbols, the units, the label and the default selections; the load of the HCTZ model of pkdb_models on the engine core takes 0.32 s instead of 0.94 s.
- **The engine core simulates a small scan on every CPU** (#690). `core_threads(None, n)` gives `min(n, cpus)` threads below the threshold of a pool, and a run of one process (`n_workers=1`) gives the engine core every CPU for its scans.
