# Release notes for sbmlsim 0.15.1
![sbmlsim](https://github.com/matthiaskoenig/sbmlsim/raw/develop/docs/images/favicon/sbmlsim-100x100-300dpi.png)

A single run of differential evolution uses every core of a fit: it evaluates its population on the workers.

Results which change: a fit of differential evolution without an explicit `updating`, which updates its population once per generation (`updating="deferred"`) instead of after every trial vector.

## Features

- **Differential evolution evaluates the population of a run on the workers of the fit** ([#433](https://github.com/matthiaskoenig/sbmlsim/pull/433)). A fit parallelized over its runs only, so a single global optimization (`n_cores=4`, one run) ran on one core, e.g. more than 4 hours for a PBPK model. A worker cannot start workers of its own, so `split_cores` of `sbmlsim.fit.runner` gives the workers either to the runs, when there are as many runs as workers or more and always for least squares, or to the population: the runs of differential evolution then run one after another, and every run evaluates the members of its population and the steps of its polishing on all workers of one pool, which the fit stops after it. A fit sets `updating="deferred"` unless it is given, and the costs return in the order of the members, so a seed gives the same optimum, cost and trajectory for any number of workers. The trajectory has every evaluation, the timeout of a run gives up the members which are not evaluated and keeps the best parameters, a member whose worker dies runs again alone and one which kills its worker alone has an infinite cost. `updating="immediate"` keeps the former results and evaluates the population serially; `workers` of SciPy is refused, `n_cores` gives the workers. On the HCTZ problem of the tests (8 ms per evaluation) one run takes 3.9 to 4.7 s on 4 workers instead of 7.8 s, a generation 2.6x less; a PBPK model with seconds per evaluation gains more.
