# Release notes for sbmlsim 0.14.1
![sbmlsim](https://github.com/matthiaskoenig/sbmlsim/raw/develop/docs/images/favicon/sbmlsim-100x100-300dpi.png)

A patch release for petab 0.10.0 and the security updates of the dependencies. sbmlsim 0.14.0 imported `SbmlModel` from `petab.models`, which petab 0.10.0 removed, so the PEtab export failed to import in a fresh install. The results are compressed with zstd, a run holds its result once and the first run of a process no longer imports the uncertainty. The simulations, the units, the fits and the figures are unchanged.

## Fixes

- **The PEtab export works with petab 0.10.0** ([#408](https://github.com/matthiaskoenig/sbmlsim/pull/408)). `sbmlsim.fit.petab_v2.export` imports `SbmlModel` from `petab.v2.models`, which petab 0.9.0 has as well, instead of `petab.models`, which petab 0.10.0 removed. With sbmlsim 0.14.0 and petab 0.10.0, `import sbmlsim.fit.petab_v2.export` raised `ModuleNotFoundError: No module named 'petab.models'`, and so did everything which exports a fit as a PEtab problem.
- **A run writes every chunk into its result when it arrives** ([#411](https://github.com/matthiaskoenig/sbmlsim/issues/411), [#415](https://github.com/matthiaskoenig/sbmlsim/pull/415)). `Simulator.run` kept every chunk until the last one arrived and copied them into the result then, so the parent held the result twice. A chunk is written into the arrays of the result and released, on a grid when it arrives and for a ragged result one after the other at the end. The peak memory of the parent over a scan of the HCTZ model (191 selections, 4000 points, 1.2 GB) is 1.76x instead of 2.02x of the result serially and 1.14x instead of 2.02x on 4 workers.
- **A run without uncertain values does not import the uncertainty** ([#413](https://github.com/matthiaskoenig/sbmlsim/issues/413), [#414](https://github.com/matthiaskoenig/sbmlsim/pull/414)). The record of a scan checked every value for an uncertain one, which imported `sbmlsim.uncertainty` and with it the fit, matplotlib and scipy.stats: about a second on the first `Simulator.run` of a process.
- **The netCDF files of the results are compressed with zstd** ([#412](https://github.com/matthiaskoenig/sbmlsim/issues/412), [#416](https://github.com/matthiaskoenig/sbmlsim/pull/416)). `ScanResult.to_netcdf` and `SensitivityResult.to_netcdf` compress the numeric variables with zstd (level 1, the HDF5 filter of the new dependency `hdf5plugin`) and the shuffle filter, in chunks of whole timecourses of about 1 MiB. `compression="gzip"` writes the filter every HDF5 reader has, `None` none. A result of the HCTZ model with 191 selections over 5000 points shrinks from 1551 MB to 136 MB.

## Dependencies

- **pillow 13.0.0 or newer** is required. pillow is not imported by sbmlsim, matplotlib writes its images with it; 13.0.0 fixes the advisories of 12.3.0, among them the critical GHSA-5x8w-8jj5-q52h, GHSA-332p-7hrc-92wf, GHSA-8g5g-8vmr-9782, GHSA-v9pv-5gc8-w2m6 and GHSA-w889-685w-c8fh.
- `uv.lock` has the security releases of the development tools: virtualenv 21.15.2 (fixed in 21.14.7 and 21.14.9: GHSA-vxj4-q4g9-crj7, GHSA-394h-qwmc-48pf, GHSA-6w3r-xr62-4xcp, GHSA-c978-59m8-c77v and eight more) and filelock 4.2.6 (fixed in 4.2.1). It also has pkpdutils 1.4.0, sbmlutils 0.17.1, pymetadata 0.8.3 and petab 0.10.0. `pip-audit` finds no known vulnerability in the lock.
- The `dev` extra excludes tox 4.67.5, which rejects its own `.tox/.tmp/package` under the umask 002 ([tox-dev/tox#4357](https://github.com/tox-dev/tox/issues/4357)).
- The dependency group of dependabot ([#404](https://github.com/matthiaskoenig/sbmlsim/pull/404), [#405](https://github.com/matthiaskoenig/sbmlsim/pull/405), [#406](https://github.com/matthiaskoenig/sbmlsim/pull/406), [#407](https://github.com/matthiaskoenig/sbmlsim/pull/407), [#408](https://github.com/matthiaskoenig/sbmlsim/pull/408)).
