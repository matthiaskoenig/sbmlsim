# Release notes for sbmlsim 0.9.5
![sbmlsim](https://github.com/matthiaskoenig/sbmlsim/raw/develop/docs/images/favicon/sbmlsim-100x100-300dpi.png)

A patch release of the fixes which the port of the models of pkdb_models onto sbmlsim 0.9.4 found.

## Fixes

- **A simulation does not depend on whether another instance of its model is alive** ([#313](https://github.com/matthiaskoenig/sbmlsim/issues/313)). roadrunner 2.10 takes the compiled model of a new instance from its cache in the process when another instance of the same SBML is alive, and gives such an instance no piecewise triggers (`createModelData(..., 0)` in `LLVMModelGenerator::createModel`), so CVODE's root finding does not stop at the switches of the piecewise functions of the model: the instance integrates a few `1e-9` apart from a compiled one. In a run of experiments the first experiment compiled its model and every later one took it from the cache, while the workers of a pool compiled theirs, so the first experiment, the later ones, a serial run and a pool run differed (0.9.4; 0.8.5 kept an instance alive from the start, so every experiment of it took the model from the cache): the first experiment of the empagliflozin, dapagliflozin and canagliflozin models of pkdb_models differed by `4.4e-10` to `4.7e-9` from a run with an instance of the model alive from the start. sbmlsim now compiles a model whenever it loads it (`load_roadrunner`, `LoadSBMLOptions.RECOMPILE`), which costs the compilation of the model once per loaded model (0.2 s for dapagliflozin, against 0.01 s from the cache), and a run with an instance alive from the start equals one without, bitwise. The compiled model is the more accurate one (on a rate which switches at a time, `3.0e-5` against `3.6e-5` from the exact solution); the results of a model with piecewise functions which ran from the cache change by the root finding at their switches, in these three models by up to `1.5e-8` (`4.5e-7` in the parameter scan of empagliflozin), the ones of a compiled model and of a model without piecewise functions do not change.
- **A point of a scan does not depend on the point before it** ([#318](https://github.com/matthiaskoenig/sbmlsim/issues/318)). roadrunner's reset computes the initial amount of a concentration species from the volume of its compartment with the parameters of the simulation before, and roadrunner reads and writes the amount of such a species through the current volume of its compartment, `(amount / volume) * volume`: an amount which the reset computed with the volume of the point before could read as the amount as loaded under the volume as loaded, so the restore of #303 did not see it, and differ from it in the last bits under the volume of the next point. In the acetaminophen model of pkdb_models, whose volume of the blood of the rest of the body is an assignment rule of the volume fractions of the organs, a point with `FVpa = 0.005` after one with `FVpa = 0.015` differed from the point alone by `1.278e-7` (0.8.5 to 0.9.4), and a point of a pool depended on what its worker ran before. The parameters and the compartments as loaded are now set back before the reset as well, so that it computes every initial value as at the load; the results of a point after another one change in the last bits, the first point of a model does not change.
- **The start values of a fit are the values of the model as loaded** ([#315](https://github.com/matthiaskoenig/sbmlsim/issues/315)). `OptimizationProblem` read the start values of the fit parameters (`xmodel`) from the current state of the first model, and the references of a design (`sampling.references`, through `parameters_of` or a design with a simulation) left that model initialized with the pre-initialization of their simulation, so `xmodel` was a value of a simulation of an experiment and not of the model; which model was first depended on the hash seed. In the midazolam model of pkdb_models `xmodel` of `GU__MIDOH_f`, `0.41166` in the model, was `15.0` or `0.05` depending on `PYTHONHASHSEED`, and the cost of the fit `ALL` at `xmodel` `32143.7` or `512492.3` instead of `41640.5` (0.8.5 to 0.9.4); it is now `0.41166` and `41640.5` for every hash seed. `xmodel` is now read from the model as loaded (`RoadrunnerSBMLModel.loaded_value`), and the references reset the model after they read it (`RoadrunnerSBMLModel.reset`), so they leave no value of the pre-initialization behind.
