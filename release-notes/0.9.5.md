# Release notes for sbmlsim 0.9.5
![sbmlsim](https://github.com/matthiaskoenig/sbmlsim/raw/develop/docs/images/favicon/sbmlsim-100x100-300dpi.png)

A patch release of the fixes which the port of the models of pkdb_models onto sbmlsim 0.9.4 found.

## Fixes

- **An empty column without a unit is no error** ([#310](https://github.com/matthiaskoenig/sbmlsim/issues/310)). `DataSet.from_df` logged `Column 'time_unit' units are missing` as an error for a unit column without a unit also when its column had no number either, e.g. the time of a table of PK-DB which does not report it (`time` and `time_unit` empty in every row): one error per dataset and load, 289 in one run of the apixaban model of pkdb_models. Such a column has no unit as before; the error is logged only when the column or its `sd`, `se`, `min` or `max` has a number, a debug message otherwise, and the same holds for the statistics of a `unit` column.
- **The classifications of the IPCS classify the magnitude and give no class for an undefined value** ([#311](https://github.com/matthiaskoenig/sbmlsim/issues/311)). `uncertainty_classification` raised a `ValueError` for a negative uncertainty, although its docstring classifies `|U|`: `U = (P97.5 - P2.5) / P50` is negative for an output with a negative median, e.g. the change of the body weight (`U = -1.66` in the dulaglutide model of pkdb_models), so a sampling analysis of such an output failed in its classification (0.8.5 to 0.9.4). It now classifies `|U|`; `uncertainty_classification` and `sensitivity_classification` return `None` for `NaN` instead of raising, and their symbols are empty, so one undefined index does not stop the classification of the others. Their return types are now `UncertaintyClassification | None` and `SensitivityClassification | None`: a caller which reads `.value` of the class handles `None` for an undefined value (a type checker reports it). An infinite value, e.g. `U` of an output whose median is 0, is classified `high`, as before.
