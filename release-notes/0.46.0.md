# Release notes for sbmlsim 0.46.0
![sbmlsim](https://github.com/matthiaskoenig/sbmlsim/raw/develop/docs/images/favicon/sbmlsim-100x100-300dpi.png)

The reductions and the PK parameters of an experiment are a fit of the engine on sbmlsim-core 0.32.0, a fit simulates the adopted fits of the other subsets it keeps fixed, and a run over the draws is faster: one array per figure, the bands at once and the threads of the engine on the CPUs the run leaves.

## Features

- **Reductions and PK parameters in the engine** (#685, fixes #625). A fit group whose data reads a reduction of a column (`max`, `min`, `mean`, `at`) or a parameter of the non-compartmental analysis of a `PK` observable is a fit of the engine (`sbmlsim.fit.reductions`): every mapping is a curve of `fit/1` with its `reduction`, the analysis of a `PK` curve is the one of pkpdutils-core in the engine, and the jacobian comes from the forward sensitivities (a central directional difference of the analysis along the sensitivities for `pk`). The residuals equal the ones of python. A formula of more than one reduction, a time of `at` which is no number, a `Custom` observable, a scan (#624), the flags of a `PK` observable, a dose which is fitted and a logarithmic or estimated noise stay gaps. The floor is `sbmlsim-core>=0.32.0`.

## Changes

- **A fit simulates the values it keeps fixed** (#683, fixes #663). `OptimizationProblem(fixed_values=)` applies the values of the adopted fits of the other subsets as changes before the initialization of every simulation whose model has the entity, in python and in the engine, so the order of `--adopt` and the factory no longer matters; a fitted value of the SBML which differs from its adopted record is a warning naming the factory. A report, an identifiability, a Fisher information and a posterior from a record simulate the values that fit kept fixed (`recorded_fixed_values`), a credibility assessment the adopted fits as they are now.
- **Runs over draws** (#687). `Data.get_data` reads, renames and converts the array of a task once per figure and selects the draws of it, `point_band` reads all draws at once; a worker which only runs python counts as one CPU and the CPUs left are shared by the processes which run threads of the engine core, the calling process counts among the busy workers, and only the most expensive experiment with a large scan stays in the calling process. A run with more than one worker and no `scan_workers` gives the engine core every CPU. `EvaluationPool` and `map_evaluations` preload the modules of their problems in the forkserver.
