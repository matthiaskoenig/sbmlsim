# Release notes for sbmlsim 0.53.0
![sbmlsim](https://github.com/matthiaskoenig/sbmlsim/raw/develop/docs/images/favicon/sbmlsim-100x100-300dpi.png)

A problem of PEtab v2 on disk is read, simulated and evaluated by sbmlsim-core: the PEtab test suite and the benchmark collection run in the engine, several times faster, and the report of a fit of the engine core no longer draws an empty figure of traces.

## Features

- **PEtab v2 in sbmlsim-core** (#713, #714, fixes #711). `sbmlsim.fit.petab_v2.core` reads a problem on disk with `sbmlsim_core.petab` and evaluates it in the engine (`evaluate`: the log-likelihood, chi2, the log priors, the log posterior and the simulation table); `log_likelihood`, `chi2`, `log_prior` and `unnorm_log_posterior` take the path of a problem as well. The runner of the PEtab test suite evaluates every case in the core (149 of 149, 0.6 s against 2.5 s in python for the model cases), the benchmark every problem except three which the core does not read yet (`CORE_GAPS`: Armistead, Beer, Blasi, see sbmlsim-core#145; 1.4 s against 15.9 s). `from_petab` keeps building an `OptimizationProblem`, whose fit runs as before. The training and the validation problems of the export of #710 evaluate to the same values in python and in the core (1e-11). The floor is `sbmlsim-core>=0.39.0`.

## Fixes

- **The report of a fit of the engine** (#715). The engine core answers with the cost of a run and not of its steps, so a fit of the engine has no traces: the report leaves out the figure of the traces, which was drawn as empty axes, and its methods assess the convergence by the waterfall plot of the final costs instead of the traces.
