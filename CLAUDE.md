# CLAUDE.md

This file provides guidance when working with code in this repository.

## Project

`sbmlsim` is a python library for the simulation of models in the Systems Biology Markup Language (SBML), built on libroadrunner, with COPASI and AMICI as a second and a third engine: timecourse simulations with changes, parameter scans, simulation experiments with datasets, figures and reports, parameter fitting and sensitivity analysis. A library with one command line, `python -m sbmlsim.run` (the run layer, `run/`), and no console scripts. Requires python >= 3.14 (3.14 and 3.15 are supported; the simulation and model workflows run on them only), packaged with hatchling (version is read from `src/sbmlsim/__init__.py`). Runtime dependencies are `libroadrunner` (simulation), `sbmlutils`, `python-libsbml` and `pymetadata` (SBML, its formulas and COMBINE archives), `numpy`, `pandas`, `xarray`, `h5netcdf` and its backend `h5py` (the netCDF files of a `ScanResult`; h5netcdf installs h5py only as an extra, so it is a dependency of its own) and `hdf5plugin` (the zstd filter of HDF5 the files are compressed with), `scipy`, `sympy`, `sbmlmath` (the math of SBML as sympy expressions), `pint`, `pydantic` (data, units, numerics), `petab`, `pyyaml`, `SALib` (fitting and sensitivity analysis), `pkpdutils` (the non-compartmental analysis of a `PK` observable, imported when one is compiled) and `matplotlib`, `seaborn`, `jinja2`, `rich` (plots and reports), `certifi` (the CA bundle of requests, with which sbmlutils and pymetadata reach the network; its floor 2026.10.19 is the fix of GHSA-6q48-6c7w-9gw2, a direct dependency only for the floor) and `pillow` (the images of matplotlib; its floor 13.0.0 fixes the advisories of 12.3.0, a direct dependency only for the floor). `python-copasi` (COPASI, the second engine of the simulator, `Simulator(engine="copasi")`) is the `copasi` extra, which `dev` and the tox environments install; `import sbmlsim` and every path of roadrunner never import `COPASI` (`tests/test_engine.py` checks it in a subprocess), and selecting the engine without it raises an `ImportError` naming `pip install sbmlsim[copasi]`. `amici` (AMICI, the third engine, `Simulator(engine="amici")`) is the `amici` extra, `amici>=1.2.0` and `ninja`, with which AMICI builds a model; it is not in `dev` and not in the tox environments, since AMICI is built from source (a C++ compiler, a BLAS library with `cblas.h` and the headers of HDF5 from the system, CMake and SWIG from PyPI), a local environment adds it with `uv sync --extra dev --extra amici`, and nothing of sbmlsim, the examples or the tests imports `amici` statically, so ty passes with and without it (see Conventions). `petab-sciml` (the networks of PEtab SciML, `sciml/`, whose weights are read with `h5py`) is the `sciml` extra, which `dev` installs; the `plain install` job of `ci-cd.yml` runs `scripts/plain_install.py` in an install without extras, which `dev` would hide a missing dependency from. `simrun` (the runner of workflows on a cluster, whose task types `sbmlsim.<kind>` are the kinds of the run layer, `sbmlsim.simrun`, entry points of the group `simrun.task_types`) is the `simrun` extra, `simrun>=0.1.0`, which `dev` installs; until simrun 0.1.0 is on PyPI the lock takes it from git (`[tool.uv.sources]`, a pinned commit; switching to PyPI is a release blocker of sbmlsim 0.17.0), the development environment is python 3.14 (`.python-version`, so ty checks `sbmlsim.simrun` against simrun) and the tox environments, which resolve from `pyproject.toml` with the extras `sciml` and `copasi`, do not install it (`tests/run/test_simrun_plugin.py` skips without it).

## Commands

```bash
# environment (uv based), the versions of the committed uv.lock
uv sync --extra dev
uv sync --extra dev --extra amici                  # with the engine AMICI, built from source (see docs/installation.md)
uv run pre-commit install
uv lock                                            # after every change of a dependency in pyproject.toml
uv lock --upgrade                                  # move the lock to the newest releases

# tests
pytest                                             # all tests, in parallel with pytest-xdist
pytest -m testsuite                                # the semantic cases of the SBML Test Suite, deselected by default
tox r -e testsuite                                 # the same, with the cases downloaded first
pytest -m petab_testsuite tests/fit                # the cases of the PEtab test suite (v1 converted), deselected by default
tox r -e petab                                     # the same, with the cases downloaded first
pytest -m petab_benchmark tests/fit                # the problems of the PEtab benchmark collection, on demand
tox r -e benchmark                                 # the same, with the collection downloaded and converted first
pytest -n 0                                        # in one process, e.g. for --pdb
pytest --skip-slow                                 # without the tests marked `slow`, as continuous integration runs it
pytest tests/simulation/test_simulation.py         # single file
pytest tests/simulation/test_scan.py::test_scan1d  # single test
pytest -rs                                         # list the skipped tests
pytest -m benchmark -n 0 -s tests/simulator/test_benchmark.py  # the speed of the scan core, on demand
tox r -e py3.14                                    # single tox env (py3.14, py3.15 available)
tox run-parallel                                   # the tests on every supported python, run before opening a pull request

# lint / format / types
ruff check
ruff format
uv run ty check                 # ty type check (config in [tool.ty] in pyproject.toml)

# analyses from the command line (docs/run.md); the HCTZ project needs the root of the repository on the path
python -m sbmlsim.run <kind> <spec> --out DIR [--workers N] [--resume] [--provenance FILE] [--input PORT=PATH] [--summary FILE]
python -m sbmlsim.run plan <kind> <spec> [-o FILE]          # the planned spec as JSON (seed, units)
python -m sbmlsim.run unit <kind> <spec> <index> --out DIR  # one unit of a planned spec
python -m sbmlsim.run merge <kind> <spec> --out DIR         # merge the units into the result
python -m sbmlsim.run list examples.hctz_fitting.project:PROJECT  # the analyses of a project

# examples, they are modules of the `examples` package and not part of sbmlsim
python -m examples.timecourse
python -m examples.sensitivity.sensitivity_example
```

`develop` is the default branch and takes every change through a pull request; direct pushes are rejected by the rulesets in `.github/rulesets/` (applied with `.github/rulesets/apply.sh`), which require the `tests`, `ruff`, `ty` and `docs` checks (`ruff` and `ty` are the jobs of `lint.yml`). Every job of the workflows sets up uv, python and the environment with the action `.github/actions/setup`, which syncs from the lock (`uv sync --locked`), and runs the commands a developer runs, without tox; a push to `develop` is never cancelled, since a release waits for the run of its commit. Continuous integration is kept minimal: `tests` runs python 3.14 on linux, macos and windows and python 3.15 on linux (h5py has no wheels for 3.15 yet, the job installs `libhdf5-dev` and builds it) and, as the job `amici engine` on linux only, the tests of the engines with the extra `amici` (`tests/test_engine.py`, every test file with `amici` in its name and `test_*_engines.py`, the build requirements installed with apt, the built wheel kept in the cache of uv), without the tests marked `slow` (`pytest --skip-slow`, the long end-to-end runs of examples), a run of a pull request is cancelled by the next push to it (`cancel-in-progress: true`), uv caches packages and interpreters (the release builds without the cache), dependabot runs monthly. Python 3.15 on macos and windows runs only locally (`tox run-parallel`). `main` only tracks the latest release and is fast-forwarded by the `sync-main` job of the release workflow, never by hand.

Release steps are in `docs/development.md` (there is no separate `RELEASE.md`): the release is prepared on a branch, `uvx bump-my-version bump [major|minor|patch]` updates `src/sbmlsim/__init__.py` and `CITATION.cff` and commits without tagging (`tag = false`, a squash merge would rewrite the commit), and the tag is created on `develop` after the pull request was merged, which triggers the PyPI release workflow; it does not run the test matrix again, its job `tested on develop` waits for the run of the push of the same commit to `develop`, which is why the runs of `develop` are never cancelled.

Documentation is [Zensical](https://zensical.org/): markdown sources in `docs/`, configured in `zensical.toml`, built into the gitignored `site/` (`uv run zensical build --clean`, `uv run zensical serve` for the preview). The API reference is rendered from the docstrings by mkdocstrings; a page in `docs/api/` is just `::: sbmlsim.<module>`, so nothing of it is generated into the repository. `docs/tutorial.md` walks through the features on the HCTZ model (`HCTZ_SBML`) and comes before the core pages. Every `python` block of a page in `PAGES` of `scripts/docs_outputs.py` runs in the order of the page in one namespace; the script writes what a block prints below it as a block titled `Output` and saves the matplotlib figures it creates (open pyplot figures and figures held by a name) as `docs/images/outputs/<page>-NN.png`, both committed and never edited by hand; `tests/docs/test_docs_code.py` runs the pages and fails when a page is out of step with its code (an output or an image missing or left over, a page with code missing from `PAGES`), without comparing the text; `docs/run.md` (the page Analyses, the run layer and simrun) has only `bash`, `yaml` and `json` blocks and is not in `PAGES`. `scripts/llms_txt.py` runs after the build and writes the agent facing files (`llms.txt`, `llms-full.txt` and the markdown of every page) into `site/`. The `documentation` workflow runs `scripts/docs_outputs.py` before the build, so the published pages never show stale outputs (#447), runs both and publishes the site from `develop`; a release writes the outputs again after the bump.

## Architecture

**`simulation/`, `simulator/`, `result/` - the simulation core.** `Simulation` (`simulation/definition.py`) is the one way to set up a simulation, used by experiments, scans, fits and PEtab: `start`/`end` in its `time_unit` (negative times allowed), `preinit_changes` set on the model before its initialization (the initial assignments see them), `changes`, a list of `Change(times, values)` at absolute times (one time or a vector, i.e. multiple dosing; a value is a number, a `Quantity` or a formula string of PEtab math over roadrunner selections, `S` amount, `[S]` concentration, `time`), `presimulation=SteadyState(...)`, and the output: the steps of the integrator by default, `times` or `steps`. The semantics are PEtab v2 (pre-initialization, simultaneous evaluation of the values of a change, compartment changes keep concentrations, a species of an assignment rule follows its rule; the output at the time of a change after the start has two rows, the state before the change and the state after it, the steps of the integrator at every change and an output of times at its times which are changes; the steps of the integrator have an event of the model as two rows as well, also an event at the end of the simulation). `Scan(simulation, dimensions)` (`simulation/scan.py`) runs it over `Dimension` objects, each of `values` (targets to arrays, coupled within a dimension; a value replaces its target wherever the simulation sets it, `Simulation.with_values`, `at=` makes it a `Change` at that time, and `Scan.__init__` logs one warning per dimension and target when a dimension without `at` replaces a target the simulation sets to different values, e.g. the stop of an infusion), `simulations` or `models`; several dimensions span their product in C order. A dimension copies its values into read-only arrays and has `labels`, which are given or default to `0..n-1` for values and to the keys otherwise; neither a dimension nor a scan changes after it was created, and a run never changes the objects of the user. `simulator/plan.py` compiles a simulation against a model (`ModelSymbols`, `UnitsInformation`) into a frozen, picklable `Plan` without units, output times closer than `TIME_RTOL * max(abs(start), abs(end), end - start)` are one output time, a cluster becoming its smallest time (`merge_times(times, start, end)` gives the merged times and the index of each given time, which `compile_simulation` and the data times of a fit share, so the rows of a fit stay aligned), and a point of a scan is that plan with other values (`Plan.with_values(values, at=None)`), never a compiled simulation; `simulator/executor.py` `execute(plan, model, selections)` runs it on roadrunner (no pint, no pandas, no xarray; COPASI and AMICI have their own executors, see the engines below); `output_columns` and `output_time` of `executor.py` are shared by the three executors: `time` is the first column, `plan.time_shift` is applied to it and a later column `time` is a copy of it, the time of the row, except for a model with an entity named `time` (case 01820), whose later column is the value of the entity (#445); every segment between two changes ends in its state at its end, which the next change is applied to: with the steps of the integrator roadrunner's variable step `simulate` interpolates its last row to the end with the dense output of CVODE and leaves the model there (libroadrunner 2.11), so a model without events needs nothing more, while for a model with events `_steps` calls the integrator once more with exact output at the end (`_to_the_end`, no integration), which fires an event roadrunner kept pending, and so does every horizon of a steady state; a horizon after whose end roadrunner fired a pending event (`_to_the_end`) is followed by the next one from the time of the model, and a horizon in which roadrunner fired an event within the resolution of the time before its end whose trigger is false at the end and true right after it (a strict trigger of the time, whose root CVODE locates a little early; an event which makes its own trigger false does not count) runs again with exact output at its end (`_EventAtTheHorizon`, `_event_at_the_horizon`, at most once per horizon), so the event fires once per crossing of the time as in COPASI and AMICI (#444); every segment of a model with events stops just before its end (`_stop`, a unit in the last place of the larger magnitude of its start and end in the time of roadrunner, which CVODE resolves, and at least four machine epsilons, below which roadrunner applies an event at the start of a call of the integrator without its rows, so the stop is never a subnormal number before an end at 0), so an event of the model at the time of a change fires after it, the last row of a segment which ends at a change, the one at the end included, is the state before the change at the time of the change, and the next segment starts with the state after it; a segment too short for CVODE (`_integrable`, its condition `CV_TOO_CLOSE`, a few units in the last place in absolute time, e.g. between two changes a few units in the last place apart) is not integrated, its state is the one at its start; the triggers before a change and at the end are evaluated at the time the model is at (`stopped`: the time of the model after the segment before, which roadrunner may integrate one unit in the last place past its stop, the start of a segment which is not integrated, `plan.start` before the first one), so an event of the time fires once whatever segments are held; roadrunner does not see a trigger which a change makes true, the executor fires such events after the change (`fire_events` of `simulator/changes.py`, which applies the changes as well, `apply_changes`, both on the values of the model through the protocol `ModelValues`, `getValue`/`setValue` of the selections of roadrunner, which `roadrunner.RoadRunner` satisfies, so the engines share them; PEtab v2 reinitialization): one at a time in the order of their priorities, which are evaluated again after every event (ties in document order, a priority which is no math of `sbml_math.compile_math`, one with `rateOf` or `delay`, is reported and counts as 0, the priority of an event without one), the triggers are evaluated again after every event as well and a pending event whose trigger is not persistent is cancelled when it becomes false, the values of the assignments are the ones at the trigger or at the execution as `useValuesFromTriggerTime` says, an event with a delay or with assignments which are no such math is reported and not fired, a trigger which is no such math is reported once per event and model instance (`RoadrunnerSBMLModel.reported_triggers`, so once per worker of a pool) and a change does not fire its event (`ModelSymbols` keeps the math of an event as MathML of selections, a concentration species as the identifier `[S]`, its function definitions expanded and the units of its numbers removed, `0.5 dimensionless` of sbmlutils, #293; `compile_math` compiles it with sbmlmath with the meaning SBML gives it, every function of the MathML of SBML but `rateOf` and `delay`, #299, the operations as written and the numbers as doubles, e.g. `q / 49` and not `q * (1/49)`, with `avogadro` the value of roadrunner and IEEE values as roadrunner computes them, NaN for the root of a negative number, infinity for a division by zero; it imports sbmlmath, 0.2 s, at the first event), and one event fires at most `MAX_EXECUTIONS_PER_EVENT` times, which stops events which trigger each other in a cycle without limiting the number of events which fire; after the last segment `_event_at_the_end` integrates the steps of the integrator to the resolution of the time after the end, pairing the rows of an event within the rounding of `at_event_times`, an event there is at the end (two rows in the steps of the integrator, the state after it at an output time at the end, after a change at the end), and the steady state after the end starts at the time of the model after it, so an event of the time does not fire twice; roadrunner integrates an exact output time from the one before it, `t + (next - t)`, which can round up to the time of the change, `_simulate_times` then puts a time between from which the sum is exact; a segment of a model with events past whose end roadrunner fired an event runs again with exact output at the times of its steps (`_PastTheEnd`, `_exact_times`, an event inside integrated to a resolution of the time before and after it, its rows at the times of the steps): the plan runs once more, after a second such segment a third time, which keeps the state at the start of every later segment in memory (`_saved_state`, `saveStateS`) that a later segment past its end starts again from, so a plan runs at most three times; `_variable_steps` hides roadrunner's warning that a negative end was not reached; after every run of a model with events `execute` applies an event which the integrator of libroadrunner 2.11 keeps pending after the steps of the integrator found its root after the end (`model_roadrunner.apply_pending_step_event`, one call of the integrator with exact output), which neither a reset nor the next `simulate` clears and which the next simulation would apply with stale trigger states (case 01590, roadrunner #1381); a delayed event fires late in the steps of the integrator, at the end of the next step of CVODE (roadrunner #1382, not worked around). `Simulator(n_workers=None, engine="roadrunner", **integrator_settings)` (`simulator/simulator.py`, the settings an `IntegratorSettings` of `model/model_sbml.py`, the names of roadrunner, a dictionary of other names goes to `set_integrator_settings`; the engine simulates every model the simulator runs, see the engines below) has `load`, `compile`, `simulate` (one `TimecourseResult`) and `run(model, scan, observables=None, *, time, keep, on_error, progress, points)`: it compiles one plan per combination of the simulations and models of a scan, cuts the points into chunks of one plan (at most `ceil(n_points / (4 * n_workers))` and `MAX_CHUNK` points) and runs them with `simulator/worker.py` serially or in the kept pool of `sbmlsim/parallel.py` (the same function `run_chunk`, a worker loads a model once from its `ModelSpec`, in the engine of the model of the parent (`ModelSpec.engine`, `load_model`), keyed on the hash of the engine, its SBML as the parent loaded it (`SBMLModel.sbml`), the added parameters, the optimization level of roadrunner (`None` for COPASI and AMICI), the directory of the compiled models of AMICI the parent loaded it from (`ModelSpec.cache`, `engine.amici_cache`, loaded under `engine.using_amici_cache`), the integrator and every one of its settings as the model of the parent has them (`SBMLModel.integrator_state`), so a setting of the model holds in a worker as well and a file rewritten or deleted after the model was loaded changes nothing; `parallel.shared_payloads` writes the SBML of the models of a run into files of a private temporary directory, one file per content, which a worker reads instead of receiving the SBML with every chunk, and removes them after the run, also after an error; a pool run keeps at most two chunks per worker pending, submitted in the order of their first point, and submits no chunk after a failed point, while the chunks before it still run; every chunk checks that its plan was compiled for the symbols and units of its model, `Plan.check_model` with `model_units`, computed once per `UnitsInformation` and again when its units or its registry change, the base unit and the scale of the unit of every entity, a factor of a unit such as `item/(31557600.0*s)` in the scale and a unit pint does not normalize as it is), and assembles a `ScanResult` (`result/scan.py`), which wraps an `xarray.Dataset` (`ds`) with the scan dimensions first and the time last, `(*dims, time)` on a common grid or `(*dims, _point)` with the native time points padded with `NaN`, the labels and the changed values as coordinates (a changed target which is also a variable or a name of the result, `RESERVED` of `simulation/scan.py`: `time`, `_point`, `_index`, `statistic` and `status`, keeps the variable and its values as `<dimension>.<target>`, which must not be a dimension or an output, and a coordinate of a dimension must not take a name of the result, an output, a dimension id or a changed target), `attrs["units"]`, `to` (`res.to({"time": "hr", "cp": "µM"})`, a new result with variables and coordinates converted and the labels kept, `time` with the times of the changes, the `cv` of a summary unchanged), `q` (`res.q["cp"]`, the quantity of a variable or coordinate, as `quantity`; one point of a ragged result without its padding; it registers pint's matplotlib support of the package registry, `units.setup_matplotlib`, so quantities plot in their units and `sbmlsim.plot.label_axes` labels an axis with its name and short unit), `attrs["changes"]` (the times of the changes after the start in the time of the result), `summary`, `interpolate` (onto a grid of the times of the simulations, a time twice at a change; `time_points` keeps a time twice which a simulation has twice) and netCDF (`to_netcdf`/`from_netcdf` through h5netcdf, the attributes as JSON; `result/netcdf.py`, shared with `SensitivityResult`, compresses the numeric variables with zstd and the shuffle filter in chunks of whole timecourses of about 1 MiB, `compression="gzip"` or `None`, and reading imports `hdf5plugin`, which registers the filter; Arrow, Zarr and npz were measured against it in #412). `points=range(start, stop)` runs a block of the flat indices of the scan in C order, in the same chunks of a plan as a run of the whole scan, allocating per point of the block only (also for a scan of more points than fit into memory), and gives a block: the dimension `_index` (`INDEX` of `result/scan.py`, in `RESERVED`) of the flat indices instead of the dimensions of the scan, every coordinate of a dimension along `_index`, and the attribute `block` (`BLOCK`: `start`, `stop`, the `shape` and `dims` of the scan and the dimension of every coordinate, `coords`); `dims` of a block is empty, `summary` and `interpolate` raise for it (`is_block`), and `ScanResult.combine(parts)` combines the blocks of a scan, in any order and also read from netCDF, to the result of the whole scan bitwise: it checks that the blocks are one scan (`_check_same_scan`, every attribute but `block` and `errors`, the variables and coordinates, compared as JSON, `netcdf.json_attributes`) and cover every point once (`_check_coverage`, naming missing and doubled points), pads a ragged `_point` with `NaN` to the longest block (`pad_points`, which the blocks of a propagation share), concatenates along `_index`, reshapes into the dimensions of the scan and keeps the `errors` of the blocks in their order, at most `MAX_ERRORS` (now of `result/scan.py`). A run reports the event `scan.chunk` per finished chunk (`sbmlsim.events`). `time=` interpolates every timecourse onto a grid in the worker; `on_error="raise"` raises a `ScanError` for the first failing point in the order of the scan with its labels and values, `"flag"` gives `NaN` and the variable `status`. The result does not depend on the number of workers: bitwise with roadrunner and AMICI, within the integration with COPASI, whose results are not bitwise reproducible across loads of a model (see the engines below). The selections of a run without observables are the ones of the model (`SBMLModel.set_selections`), with observables `time`, what the needed observables read and the selections `keep` names, which the result keeps as timecourses of their own names; the changes of a model are defaults of the pre-initialization changes (`Simulator.compile`). `sbmlsim/parallel.py` owns every pool of the package: `process_context()` is the start method (see Conventions), `pool(n)` is kept per process and number of workers and replaced when it broke or was shut down, `start_pool(n)` is a new pool which its caller stops with `stop` (it terminates the workers and waits for the thread of the pool, the only one which waits for the workers, since two waiting threads race under `spawn`) and whose workers call an `initializer` of the caller when they start, `shutdown` stops the kept pools (at exit), `worker_cache(key, factory)` keeps objects in a worker (the models of a scan, the problem of a fit) and `resolve_workers(n_workers, n_tasks)` turns `n_workers` into processes: `1` is serial in the calling process, a number is taken as given, `None` is every CPU of the quota (`cgroup.available_cpus`) from `POOL_THRESHOLD = 256` tasks (measured by `tests/simulator/test_benchmark.py`) and serial below and inside a worker, which never starts a pool. A worker ends when the process which started its pool ends, also when that one was killed or crashed (`parallel._end_with_the_parent`, a thread which waits for the sentinel of the parent and calls `os._exit`, #316; a busy worker when its call of roadrunner returns, which holds the GIL; under `fork` a child the parent forks outside sbmlsim inherits the watched pipe), and with the workers the forkserver and the resource tracker, which end with the last process which uses them. The workers ignore SIGINT (on POSIX they start with it blocked, so Ctrl-C does not reach a worker which still imports), the parent stops the pool of a run which Ctrl-C interrupts, and a failing point is reported by its error (the messages of SUNDIALS follow the log level of roadrunner, which a chunk lowers). `Simulator.run` computes observables from every simulation: `Formula` (a formula of PEtab math over the selections and other observables, with the reductions `max`/`min`/`mean`/`at` over the time of each simulation), `PK` (the non-compartmental analysis of pkpdutils, every parameter a value per simulation `<id>.<parameter>`) and `Custom` (a function of a module, `function(time, values)`), defined in `simulation/observables.py`, frozen and picklable. `simulator/observables.py` holds `compile_observables`, which orders them, checks the symbols against the first model, derives kinds (value per simulation or timecourse) and units (a declared `unit` is the unit of the observable everywhere, the factor from the derived unit is applied when the formula is evaluated; mixed scales of one dimension raise), prunes to what `keep` needs and gives the picklable `ObservableGraph`; a run without observables has the `identity_graph` of the selections. `simulator/pk.py` finds the doses from the plans (the values assigned to the dose target and their times), the parameters by a probe analysis of the plan of the first point of every simulation and model, which counts every assignment of the dose target as a dose, a zero value included (so a zero first dose keeps the dose parameters, while a point's own zero doses are dropped and give `NaN`), analyses the points in groups of the same number of doses and of the same padded length, the next power of two of their time points, padded with `NaN` (`_padded`, which depends on a point alone, so a parameter does not depend on the chunking, and points of the steps of the integrator, every one of its own length, share a call of pkpdutils) on the timecourses without the states before the changes (`without_states_before`, pkpdutils takes a time once and its first value at the time of a dose as the state after it; `ScanResult.to_timecourses` hands over the same) and imports pkpdutils lazily. A run with observables stacks the native solutions of a chunk and evaluates the graph on them before it interpolates, on a chunk at once and after a failure point by point, so a point fails exactly when its own simulation or observables fail; a run without observables interpolates every solution onto the grid right after `execute` and never stacks them. The result keeps timecourses over `(*dims, time|_point)` and values per simulation over `dims` (no time dimension when all kept observables are values), the definitions in `attrs["observables"]`; the functions of a point of `result/scan.py` (`point_timecourse`, `state_after_changes`, `start_values`, `end_values`, `point_band`, `single_dimension`, `scan_dimensions`) read a result with the state after a change only, on both layouts, without importing the simulator; `ScanResult.nca`/`to_timecourses` hand a PK analysis and a timecourse over to pkpdutils, and `nca` flags a failed point `NCAFlag.NO_DATA`. `simulation/sampling/` is the sampler: distributions (`Uniform`, `LogUniform`, `Normal`, `LogNormal`, `Truncated`, `Empirical`, `Fixed`, each with `ppf(u, reference)`; `FitReport(identifiability=...)` adds the section with the profiles and `cli.identifiability_cli` is the tool for stored parameters. `fit/fisher.py` is the local analysis next to it: `fisher_information` builds `FIM = J'J` from one jacobian of central differences of the weighted residuals in the space of the `parameter_scale` (step `default_step`, the cube root of the relative tolerance of the settings, unless given; `DEFAULT_STEP` 1e-6 is the step of an old record without one) and gives the standard errors, the correlations, the confidence intervals `θ ± t·SE`, the eigenvalues, the rank and the condition number, so a direction the data does not constrain is found without scanning; `FitRun.fisher()` computes it for a finished fit and `FitReport(fisher=...)` writes it into the same identifiability section, which `identifiability_cli` does unless `--no-fisher` is given. Pickling an initialized `OptimizationProblem` gives its uninitialized definition (`__getstate__`), which is what the workers need. `fit/variability.py` is the variability between the subjects of a fit: `Variability(factors, covariance, between)` holds a relative distribution per target (`LogNormal(cv=)`, a distribution with a location is refused), correlated by `Covariance`s of the targets (a correlation of the normal scores or the omega of the logarithms, `scale="log"`, through `uncertainty.draws`), `draw(n, seed, design, start)` the factors of `n` subjects, `between` the variability between the studies (a `Variability` without one of its own), whose factors the subjects of a study share and multiply (`subject_predictions(study=)`, `predictive_check(studies=16)`: the subjects of a vector are `studies` blocks of `n_subjects`, the study factors a sequence of the seed + 1, a virtual group drawn within a study; `PredictiveCheck.n_studies`); `OptimizationProblem.evaluations`/`predictions(x, indices, factors=)` evaluate a subject: `evaluated_plan(factors=)` multiplies, after the parameters, the point and the derived changes, every value the plan assigns to a target (preinit, steady state, events, `Plan.scaled`, a formula refused) and sets a target the plan does not assign to its loaded value times the factor (`Plan.assigned`), so the subjects vary around the inputs of every study group; `subject_predictions` evaluates `n` subjects (a failed integration is a `NaN` row, counted) and `predictive_check(problem, parameters, variability, n_subjects, quantiles, groups, seed)` nests them in parameter vectors (the subjects of a vector consecutive points of one sequence), compares a data point of `N` subjects (`y_counts`, 1 without) with the means of `groups` virtual groups of `N` subjects drawn with replacement (the geometric mean for a mapping with `y_errors_log`), pools the vectors and gives the quantiles as `q<percent>` columns of `PredictiveCheck.points`, `coverage` and `coverage_by_mapping`; tests `tests/fit/test_variability.py` on an antimony decay. `fit/petab_omex.py` packages PEtab v2 problems as archives. `fit/petab_v2/` is the PEtab v2 layer: `export.py` writes an `OptimizationProblem` as a PEtab v2 problem (models, conditions/experiments from the timecourses, observables and measurements from the fit mappings, parameters, a versioned parameter as a condition which assigns its target the value of the estimated parameter), `reader.py` reads one back and builds a `SimulationExperiment` subclass at runtime, resolving such a condition into a `FitParameter` selected by `helpers.filter_keys`, i.e. by the mapping ids the condition covers rather than by the selector which chose them, `extension.py` is the `sbmlsim` block of the problem YAML which carries what PEtab drops (units, `FitSettings`, mapping kinds, mapping weights, the output grid) so a round trip is exact, an observable of the problem which is a formula rather than an entity is read as an `ObservableModel` (`fit/objects.py`, the formula in the selections of roadrunner with placeholders and their values per measurement), which the fit evaluates on the simulation at the data, so the model is not rewritten, and `gaps.py` is the catalogue of the differences with `gaps_of_problem` reporting the ones a given problem hits. `sbmlsim` reads PEtab v2 only: `PetabReader.from_yaml` refuses a problem of PEtab v1, and `conversion.py` converts one with `petab.v2.petab1to2` together with its reference simulations (`convert_v1`, `convert_simulations`: the problem with the simulations as its measurements is converted too, so they get the experiments of the measurements), which the test suite and the benchmark collection do once at the download; nothing after it reads PEtab v1. `testsuite.py` runs the PEtab test suite (a pinned commit, cached like the SBML Test Suite with the directory `petabtests/cases`, `SBMLSIM_PETAB_SUITE_PATH`, the cases of PEtab v2, `sbml` and `math`, and the cases of PEtab v1 converted to PEtab v2 into `v1.0.0-converted`, the group `v1/sbml`): a case of a model is read, simulated at the nominal values of its parameter table and compared on llh, chi2, simulations, log prior and log posterior, a math case compiles its expression with `compile_formula`; `scripts/petab_testsuite.py` writes and checks `tests/data/petab_baseline.json` (with `sbmlsim.testsuite.baseline`, which the SciML suite shares) and the cases are tests with the marker `petab_testsuite`. `benchmark.py` is the same for the benchmark collection (a pinned commit, `SBMLSIM_BENCHMARK_PATH`; a problem is its encoding of PEtab v2 of the collection where it has one, else its encoding of PEtab v1 converted, written into `v2/<problem>` with the simulations of the collection converted to PEtab v2, `simulations.tsv`; the log-likelihoods of AMICI of a release, `AMICI_COMMIT`; `EXCLUDED_PROBLEMS` are not run, `Froehlich_CellSystems2018` takes too long, and `PROBLEM_SETTINGS` gives a problem a tighter integrator): a problem is simulated once at its nominal values and compared with the simulations of the collection, matched by row or by their keys, and with the log-likelihood of AMICI; `scripts/petab_benchmark.py` runs the problems in parallel with a time limit and keeps `tests/data/benchmark_baseline.json`, marker `petab_benchmark`. **`sensitivity/` - sensitivity analysis.** The analyses are functions of a `ScanResult` whose scan has a design of `sbmlsim.simulation.sampling`: `local` (central differences at the reference, `raw` and `normalized`), `sobol` (`S1`, `ST`, `S2` with intervals), `fast` and `morris` (`indices.py`) read the record of the design from the result (`design_of`), recreate the unit cube of a SALib design (`unit_cube`) and compute the indices of every observable for every label of the other dimensions and every time point of a timecourse on a grid (a ragged timecourse raises); `SensitivityResult` (`result.py`) holds them as `<observable>.<index>` over `(parameter, *dims, [time])` with units and netCDF, `index(name)` stacks the scalar observables, `classify` applies the classification of the IPCS (`classification.py`); `plots.py` draws `plot_heatmap` (its figure first as large as its labels, an observable wider than its cell rotated before the first layout, so constrained layout never collapses the axes, #314), `plot_indices` and `plot_morris`, `uncertainty.py` the bands and distributions of a scan over draws. There is no simulation loop and no pool in the package: every simulation runs through `Simulator.run`.

**`uncertainty/` - uncertainty quantification.** `Uncertain` (`quantity.py`) is a nominal value with a distribution of `simulation/sampling` (from `sd`/`cv`, a positive value log-normal with that mean and SD by default, `shape="normal"` opt-in, `low`/`high` truncate; `range`, `interval`, `se`; `kind` `uncertainty`/`variability`; `name` or the same object makes one random variable). A `Change`, the pre-initialization changes and a `SteadyState` accept it: the plain fields keep the nominal (`Change.values`, `Simulation.preinit_changes`), so every consumer simulates the nominal bitwise, and the declarations are kept apart (`Change.uncertain`, `Simulation.uncertain_preinit`, `SteadyState.uncertain`, `Simulation.uncertain_values()`, `nominal()`; `with_values` drops replaced ones; JSON `{"uncertain": ...}`; the PEtab export writes the nominal, gap `uncertain-value`). `FitParameter(prior=)` takes a distribution or an `Uncertain`, converted to the PEtab `Prior` (`Prior.from_distribution`/`to_distribution`). `Covariance` (`covariance.py`) is a covariance (linear or log scale, units) or a correlation (matrix or pairs), validated PSD, `nearest=True` (Higham). `UncertaintyModel` (`sources.py`) gives the `Variable`s of the scenarios: the inputs (by object or name, a target set uncertain and otherwise raises) and the `parameters`; `from_covariance`. `draws.py` draws scrambled Sobol (or LHS, random) points continuing from `start`, correlated through the normal scores (`normal_score_correlation`: exact for normal, log-normal on the log scale and linear covariances of log-normals; a Gaussian copula otherwise; variances must match the marginals). `propagate` (`propagation.py`) runs the draws as a `draw` dimension of a `Scan` per scenario with common random numbers (an input only where declared, a parameter everywhere, which a scenario must not set; the outputs are one value per draw), adaptively doubling until the 95 % half widths of mean, SD and 5/95 % quantiles are within `rel_tol` (0.1) of the SD (JCGM 101), and returns `UncertaintyResult` (a `ScanResult` per scenario, `summary` with MC errors of `statistics.py`, `values`, `contrast`, `contributions` by the given-data first-order index, `probability`, a directory with netCDF and `record.json`). `Propagation` (`propagation.py`, which `propagate` runs) is the propagation in blocks of draws: with `n` its `blocks()` of `block_size` draws (one block without) run separately (`run_block`) and merge in `run()` to the result of the whole propagation, every block taking its rows of the `n` points of the design drawn once, so a Latin hypercube stays one hypercube, and the adaptive number of draws runs its rounds as blocks of the continued sequence; with `checkpoint` every block of every scenario is written atomically as `<checkpoint>/<quoted scenario>/draws-<start>-<stop>.nc` (the name percent-encoded by `urllib.parse.quote`, `.` and `..` as `%2E`, names which differ only in case refused) with the fingerprint of its configuration (the attribute `propagation`: the SHA-256 of the loaded model, the engine, the integrator settings, the observables, `keep`, the grid of times and `on_error`, compared with the scan of the block when it is read and removed), read instead of simulated when it exists for every scenario (`checkpointed`), refused when it is the block of another propagation, and used as it is read also after it ran, so the result does not depend on whether a block was simulated or read; a ragged timecourse is padded to the longest block (`pad_points`), and every block reports the event `propagation.block`. `testing.py` has the probability statements, anytime valid so that they do not depend on the number of draws (the beta-binomial confidence sequence of Lai 1976, intersected over the numbers of draws; decisions `accepted`/`rejected`/`equivalent` within a `margin`, 0.05 by default, or `undecided` with `n_needed`; a direction once shown is kept, so more draws never reverse a decision), `Hypothesis` (an output of a scenario or a contrast, `UncertaintyResult.test`, `propagate(hypotheses=)` draws until decided) and `TestReport` (the decisions at the level of Bonferroni with simultaneous intervals, `TestResult.at_level`: every statement with a threshold has a true null, so a correct decision must not relax the level of the others; the decisions of a report are never reversed either); `propagate(hypotheses=)` draws random points by default, for which the statements are exactly valid. A `NaN` draw failed, an infinite one is a value; an input of one key with other distributions in other scenarios is drawn at the same quantile (`Variable.by_scenario`); a Latin hypercube needs a fixed `n`, Sobol and random points continue their sequence. MAP, the Laplace posterior, virtual trials, model uncertainty and predictive checks are later milestones; MCMC is evaluated in #374.

**Formulas.** The math of PEtab is compiled by `simulator/formula.py` (`compile_formula`, parsed by `parse_math`, the parser of `petab.v1.math` imported from its directory as `sbmlsim._petab_math` without the package `petab`, which imports matplotlib.pyplot, scipy.stats and with its SciML extension torch, 1.0 to 1.4 s per process and worker; a process which imported petab uses it), which also holds the reductions shared by observables and `Data` (`reduce_formula`, `evaluate_reduced`: `max`/`min`/`mean`/`at` over the last axis, identifiers with a dot are one symbol). A `Data` of type `FUNCTION` (`data.py`) is a formula of PEtab math, compiled with `compile_formula`; `data.evaluate_function` evaluates it on labelled arrays broadcast by dimension name and adds the reductions `max`/`min` of a single argument along the time dimension (`time` or `_point`), else the rows of a dataset (`mean` and `at` are for observables, which have the times). The math of SBML is read with sbmlmath by `sbml_math.py` (`MathMLParser`: the truncating `rem` and `quotient` of SBML, a number in e-notation as the double of its text; `log_quotient`; `math_function`, the numpy function of the operations as written and the numbers as doubles, and `compile_math`, the math of the events with the doubles of roadrunner); `sciml/formula.py` reads and writes the math of SBML with it (`formula_expression`, the expression with rationals which the compiler writes back, `evaluate_formula` through `math_function`, #420, `expression_to_astnode`) for the network compiler and the hybridization. SED-ML and COMBINE archive support (`combine/`) was removed in 0.7.0, a fit is exchanged as a PEtab problem instead.

**`comparison/` - comparison of results.** `diff.py` holds `DataSetsComparison`, which takes a `pandas.DataFrame` or an `xarray.Dataset` (e.g. `ScanResult.ds`) per simulator, matches the columns of the results of two simulators and reports the absolute and relative differences above the tolerances. `examples/comparison/` produces such results with the engines `copasi` and `amici` of sbmlsim (`simulate_engine.py`, `example_comparison.py` skips an engine without its extra; `icg_amici_simulation.py` compares AMICI with roadrunner on the ICG models); `examples/comparison/diff_example.py` compares roadrunner with JWS Online.

**`testsuite/` - the SBML Test Suite.** `SemanticCase` (`testsuite/cases.py`) is a semantic case on disk, read from its `NNNNN-settings.txt` and its `NNNNN-model.m` (`componentTags`, `testTags`), not from the SED-ML it also ships; `SemanticSuite` is a directory of cases with the download and the cache of a release under `~/.cache/sbmlsim/test-suite/<version>/` (`SBMLSIM_TEST_SUITE_PATH` overrides it). `SUITE_VERSION` pins the release the tests and the documentation run against, a release resolves `latest_version()` instead and `.github/workflows/testsuite-pin.yml` opens the pull request which adopts a newer one. `run_case` (`testsuite/runner.py`) simulates a case in the newest encoding it provides and answers with a `CaseResult` and its `CaseStatus` (`PASS`, `TOLERANCE`, `NOT_READ`, `SIMULATION_ERROR`, `MISSING_VARIABLE`, `REPEAT`) rather than raising; a case which passes is simulated again on its loaded model, the same simulation, the simulation after one of half its duration and a steady state against a fresh model, and each must equal the first bitwise (`REPEAT` otherwise, #305, `repeat_check`; the cases tagged `RandomEventExecution` within their tolerances where a regeneration draws from the generator), with the random generator of the model, which orders simultaneous events of equal priority in libroadrunner, seeded before every simulation (`seed_event_order`, `setSeed(seed, False)`); the model is initialized with `reset_all`, the binding of `resetAll`, because a model with a species or parameter named `reset` hides the roadrunner method of that name for every instance created afterwards (case 00952). `compare_case` (`testsuite/comparison.py`) applies `comparison.diff.within_tolerance`, i.e. `|c-u| <= abs_tol + rel_tol*|c|`, which `DataSetsComparison` shares. `TestSuiteReport` (`testsuite/report.py`) renders the run into the interactive page `resources/templates/testsuite_report.html`, aggregated over the tags and filtered by outcome. `scripts/testsuite.py` is the command line (`download`, `run`, `report`, `baseline`, `submission`), `run_suite` (`testsuite/runner.py`) and `write_submission` (`testsuite/submission.py`) run the cases in one process per core through `map_cases`, on the kept pool of `sbmlsim.parallel`; only the timecourse cases are run, in one encoding per case (a case which passes is simulated again by the repeat checks of `run_case`), and `tests/testsuite/test_semantic.py` is one test per case against `tests/data/testsuite_baseline.json`, which fails both on a regression and on a case which passes and is still listed. The cases carry the `testsuite` marker and `addopts` deselects it, so they are not part of a normal run: they answer what libroadrunner supports, which a change to `sbmlsim` rarely moves. The `testsuite` job of `ci-cd.yml` runs them on a tag and the release waits for it; the documentation generates the report on `develop` and not on a pull request.

`licenses.py` writes the license texts of a model (`License`, `license_text`, `write_license`; CC BY-SA 4.0 and MIT, `resources/licenses/`, byte for byte the files of pkdb_models, `-text` in `.gitattributes`) and `distrib.py` is the grammar of the distrib formulas of the fitted parameters (`parse`, `support`); both, `result/scan.py` and `units.py` import no roadrunner (`tests/test_imports.py`), the PBPK library of pkpdsim imports them. `console.py` (rich console, for scripts and examples) and `log.py` provide the shared output/logging. Modules get their logger from the standard library with `logging.getLogger(__name__)`. The package never configures logging: `log.enable_rich_logging()` is the opt-in for scripts. Library code logs, it does not print, and log calls use lazy `%s` formatting rather than f-strings (enforced by ruff `G`).

## Conventions

- Type checking is done with [ty](https://docs.astral.sh/ty/) (mypy was removed in 0.6.0). `[tool.ty.terminal] error-on-warning = true` means warnings fail the check, so the tree must stay at zero diagnostics. Suppress a diagnostic with a rule-specific `# ty: ignore[rule-name]`, never a blanket `# type: ignore`. ty also runs as a pre-commit hook (`--extra dev`).
- libsbml and roadrunner have no type stubs and build their objects through SWIG, so annotate their objects explicitly and use the getters (`getId()`) rather than the attributes SWIG synthesizes. `RoadrunnerSBMLModel.r` is `None` until a model is loaded; use `r_loaded` or check for `None` before using it.
- Every module, class and function of the package carries full type annotations and a docstring (ruff `D`, google convention); `examples/` and `tests/` are exempt from the docstring rules. Newer docstrings are google style, older ones still use the `:param:` form.
- `examples/` at the top level holds the runnable examples, they are not part of the package and are run as modules (`python -m examples.timecourse`). An example writes into the current working directory and never opens a window; the `conftest.py` at the root selects the `Agg` backend for the test session and puts the repository on `sys.path`. `tests/examples/test_example_scripts.py` runs the examples which need no optional tool, `examples/README.md` lists them. `examples/hctz_fitting` is the reference problem of the parameter fitting, `tests/fit/` builds its fixtures from `examples.hctz_fitting.fitting.fitting.op_hctz`.
- A subclass marks every method it overrides with `typing.override` (ty reports a misspelled one), and a `SimulationExperiment` defines its methods in the order of their dependencies: `datasets`, `models`, `simulations`, `observables`, `tasks`, `data`, `fit_mappings`, `figures`; `tasks` reads `self._simulations` rather than calling `simulations()` again; the data of `data()`, the fit mappings and the figures all count for the selections and observables of a task.
- The packaged models live in `src/sbmlsim/resources/models/` and are named in `resources/__init__.py` (`REPRESSILATOR_SBML`, `DEMO_SBML`, `MIDAZOLAM_SBML`, `HCTZ_SBML`, the model of the tutorial and of `examples/hctz_fitting`); test fixtures live in `tests/data/`.
- `amici` is never imported statically, neither in `src` nor in `examples` or `tests`: the `ty` check and the ty hook run without the extra, so AMICI is imported through `sbmlsim.engine.import_amici` (and its submodules with `importlib`), its objects are `Any`, and a test of AMICI skips without it (`pytest.importorskip("amici")`, the engine-parametrized tests through `tests/engines.py`). `COPASI` is installed by `dev` and is not ignored; it is imported through `sbmlsim.engine.import_copasi` in `model/model_copasi.py` (which `executor_copasi.py` imports it from), never by the modules a run of roadrunner imports, and a test of COPASI skips without it (`import_copasi` first, so the locale is kept, then `pytest.importorskip("COPASI")`).
- A pool comes from `sbmlsim.parallel`: `parallel.pool(n)` is kept per process and size, `parallel.start_pool(n)` is stopped by its caller (the fit), both use `parallel.process_context()` (`scripts/petab_benchmark.py` still creates `process_context().Pool(...)`), never the default context, which would fix the start method of the process: a start method set with `multiprocessing.set_start_method` is used, else the default of the platform (`forkserver` on linux, `spawn` on macOS and windows; no default forks, a fork of a process which runs threads may deadlock, and a worker of pytest-xdist runs threads). The fixture `_no_fork_of_threads` in `tests/conftest.py` fails a test which forks such a process, since python clears its warning after raising it and `filterwarnings = error` cannot turn it into a failure. The autouse fixture `_no_pool_left` in `tests/conftest.py` stops the kept pools after every test, so a test leaves no workers behind.
- Library code does not call `plt.show()`; figures are returned or saved, `show_figures` defaults to `False`. A figure of the package is a `matplotlib.figure.Figure` and never one of `pyplot`, whose backend is interactive with a display (TkAgg): the garbage collector releases the objects of Tk of a closed figure in whatever thread it runs, e.g. a thread of a pool, and Tk aborts the process (#317). The fixture `no_pyplot` of `tests/conftest.py` fails a test in which a figure is created with `pyplot`; only `SimulationExperiment.show_mpl_figures` and the figures of `figures_mpl()` of a user use `pyplot`.
- The examples of the documentation are quantities first and set no `steps`: results are read with `res.q[...]`, converted with `.to(...)`, plotted as quantities and labelled with `label_axes`; a common grid where one is needed (bands, summaries, timecourse indices) is `time=` of the run.
- Markdown carries no hard line wraps: a paragraph, a list item or a table row is a single line and the wrapping is left to the editor. Code fences, headings and the rows of badges keep their line structure.
- `uv.lock` is committed and pins the environment for linux, macOS and windows: the local `uv sync`/`uv run`, every job which syncs through `.github/actions/setup` (`uv sync --locked`, which fails when `pyproject.toml` and the lock disagree, so a change of a dependency comes with its `uv lock`) and the ruff of the `ruff` check (`version-file: uv.lock`). Not locked on purpose: the `plain install` job (`pyproject.toml` as a user installs it, the newest releases within the bounds), the tox environments and the `uvx` tools of the release. Dependabot moves the lock monthly in one grouped pull request (`build` prefix, `versioning-strategy: lockfile-only`, so the lower bounds in `pyproject.toml` only change by hand); the revisions of the ruff and ty hooks in `.pre-commit-config.yaml` follow the locked versions and are raised by hand.
- Release notes go in `release-notes/` as part of a release commit.
